# IQ Forge

Десктопное GUI-приложение для приёма и передачи IQ-сигналов через SDR-оборудование.

![TX: генератор, спектр, водопад, I/Q](assets/screenshots/tx_overview.png)

## Возможности

### Интерфейс
- **Device** и **Control** закреплены в левой колонке и не дублируются на каждой вкладке — единая панель Control показывает управление той вкладки (TX, RX или Signal Viewer), что сейчас открыта в основной области.
- Вкладки **TX / RX / Signal Viewer / SpectrumViewer** в основной области включаются и выключаются независимо друг от друга в Settings ("Main area tabs") — выключение вкладки просто прячет её, не останавливая ничего, что работает под капотом.
- **Help** — встроенная построчная справка по каждой панели и элементу управления, сворачиваемыми разделами по темам.

![Help: сворачиваемая построчная справка по каждой панели](assets/screenshots/help.png)

### Поддержка устройств
- **PlutoSDR** и **HackRF**, с автоматическим поиском по USB/сети (mDNS/Avahi для PlutoSDR).
- Настраиваемые частота дискретизации, центральная частота, полоса пропускания, усиление TX/RX.
- **TX1/TX2 и RX1/RX2** (только PlutoSDR) — выбор физического канала; TX2/RX2 требуют прошивку 2T2R, иначе Connect завершится ошибкой на одноканальном устройстве.
- **Режим усиления RX** (только PlutoSDR): Manual, AGC slow, AGC fast — у HackRF аппаратного AGC нет, усиление RX всегда ручное.
- Настраиваемый **размер FFT** (256…32768) — определяет частотное разрешение спектра/водопада; действует сразу и общий для TX и RX.
- Проверка связи с устройством в реальном времени — интерфейс сразу показывает, если устройство отключилось.

### Генерация сигнала (TX)
- Встроенный генератор с несколькими типами сигналов:
  - Одиночный тон
  - Мульти-тон
  - Чирп (линейная ЧМ, вверх или вниз)
  - Прямоугольный импульс
  - Баркер-кодированные BPSK-последовательности (все стандартные коды, длины 2–13)
  - Шум
  - Пила (ramp)
  - ПСП (PRBS) — псевдослучайная битовая последовательность на стандартных LFSR-полиномах (PRBS7…PRBS31), опционально с QPSK+RRC-формированием (см. ниже).
- Опциональная импульсная огибающая — любую форму сигнала (например, чирп) можно "открывать/закрывать", получая импульсный радароподобный сигнал. Форма огибающей настраивается отдельно: прямоугольная (жёсткое включение/выключение), sinc (sin(x)/x, несколько боковых лепестков), Gaussian или Hann — более плавные формы заметно сужают боковые лепестки спектра импульса по сравнению с прямоугольной.
- **Добавление шума** — подмешивает комплексный гауссовский шум к любому сигналу генератора на заданном SNR относительно Amplitude; применяется после огибающей импульса, так что уровень шума остаётся непрерывным даже между импульсами. Пригодится, чтобы проверить приёмный тракт при контролируемо ухудшенном SNR вместо чистого сигнала.
- Передача из загруженного IQ-файла вместо генератора, с опциональным зацикливанием и ресемплингом при загрузке (см. ниже).
- Живое превью сигнала (временная область + спектр), ещё до нажатия Start TX — параметры применяются мгновенно, генератор (или загруженный файл) непрерывно считается в фоне и просто не уходит в эфир, пока TX не запущен.

![Импульс с sinc-огибающей: заметно более узкие боковые лепестки спектра, чем у прямоугольного импульса](assets/screenshots/tx_pulse_envelope.png)

#### ПСП (PRBS) и QPSK-формирование

- **PRBS polynomial** — выбор стандартного полинома LFSR (PRBS7…PRBS31), **Bit rate** — скорость битового потока.
- **QPSK + RRC shaping**: выключено — передаются сырые биполярные чипы (по одному ±amplitude-сэмплу на бит, как у Barker); включено — пары бит превращаются в QPSK-символы, сформированные фильтром корень-приподнятого косинуса (настраиваемый **RRC roll-off**) — например, чтобы подать известную битовую последовательность на вход демодулятора/ПЛИС под тестом.
- Комбинируется с импульсной огибающей и с добавлением шума выше — все три включаются независимо.

![PRBS + QPSK/RRC-формирование с добавленным шумом (SNR)](assets/screenshots/tx_prbs_noise.png)

#### Загрузка IQ-файла и ресемплинг
Raw-форматы (`.cf32`/`.ci16`) не хранят частоту дискретизации, с которой записаны — поэтому при включении **Resample on load** её нужно указать вручную:
- **File sample rate** — частота, с которой реально записан файл.
- **Resample coefficient** — дробный коэффициент пересчёта (не обязательно связан с частотой устройства — можно поставить любой).
- **Resulting rate** — вычисляется и показывается сразу (File sample rate × coefficient); если она не совпадает с текущей частотой дискретизации устройства, рядом жёлтым предупреждением об этом и напишет — сигнал в эфире будет ускорен/замедлен на разницу.

При первом включении Resample on load коэффициент подставляется автоматически так, чтобы Resulting rate сразу совпала с частотой устройства — дальше его можно свободно менять.

По кнопке **Load** файл читается и (если включено) ресемплится через libsamplerate (sinc-интерполяция с корректным антиалиасинговым фильтром — работает и на повышение, и на понижение частоты), сразу становясь виден в TX-панели (сигнал + спектр), ещё до Start TX — так же, как и с генератором. **Start TX** просто продолжает уже загруженный источник, без повторного чтения файла. Без ресемплинга (чекбокс выключен) файл используется как есть.

### Приём (RX)
- Живой просмотр принятых сэмплов во временной области и спектре.
- Прокручиваемая водопадная диаграмма (waterfall/спектрограмма).
- Запись принятых IQ-сэмплов на диск по требованию — в SigMF (по умолчанию) или в сыром CF32 (см. ниже).

![RX-панель без подключённого устройства: та же раскладка, что и у TX](assets/screenshots/rx_overview.png)

### Просмотр файлов без устройства (Signal Viewer)

Отдельная вкладка для загрузки, предпросмотра, ресемплинга и сохранения IQ-файлов вообще без подключения устройства — независимо от файлового источника на TX-панели.

- **Load** работает так же, как загрузка файла на TX: фоновый поток с прогресс-баром, опциональный ресемплинг при загрузке, автоматическое восстановление sample rate и центральной частоты из SigMF.
- **Loop preview** — зациклить предпросмотр сигнала/спектра.
- **Save** записывает именно то, что сейчас загружено (уже отресемплированное, если это было включено) в SigMF или сыром CF32 — если нужна другая частота дискретизации на выходе, сначала включите ресемплинг при загрузке.

![Signal Viewer: загруженный и просматриваемый IQ-файл без подключённого устройства](assets/screenshots/signal_viewer.png)

### Широкополосный обзор спектра (SpectrumViewer)

Для сканирования диапазона частот, который шире, чем устройство способно захватить за одно измерение.

- **Bands** — один или несколько именованных диапазонов, задаваемых как Start/End либо как эквивалентные Center/Span.
- **Start sweep** запускает сканирование выбранного диапазона: устройство перестраивается шаг за шагом (шаг равен текущей Sample rate), а составной спектр заполняется по мере прохождения.
- Sweep временно берёт RX под свой контроль — **Stop sweep** останавливает RX только в том случае, если это сделал сам sweep; если RX уже был запущен независимо, он остаётся работать.
- По умолчанию скрыт: включается чекбоксом **SpectrumViewer** в Settings → "Main area tabs" (см. ниже).

![SpectrumViewer: заданные полосы сканирования перед запуском sweep](assets/screenshots/spectrum_viewer.png)

### Работа с IQ-файлами
- Загрузка и сохранение IQ-файлов в распространённых форматах:
  - Raw interleaved float32 (`.cf32`/`.fc32`)
  - Raw interleaved int16 (`.ci16`/`.sc16`)
  - PCM16 stereo WAV (`.wav`)
  - [SigMF](https://sigmf.org) (`.sigmf-data` + `.sigmf-meta`) — см. ниже.
- Встроенный диалог выбора файлов.

#### SigMF

Сырые `.cf32`/`.ci16`/`.wav` не хранят вообще ничего, кроме самих сэмплов — ни частоту дискретизации, ни центральную частоту, ни то, чем и когда сигнал был записан. [SigMF](https://sigmf.org) — открытый формат метаданных для IQ-записей (используется GNU Radio, gr-iqengine, различными SDR-инструментами), решающий ровно эту проблему парой файлов с общим именем: `<name>.sigmf-data` (те же самые сырые сэмплы, побайтово идентичные CF32) и `<name>.sigmf-meta` (JSON-метаданные рядом).

На RX-панели **SigMF** — формат записи по умолчанию (переключается на **Raw CF32** тем же радио-переключателем, где выбирается путь). При **Save & clear** в `.sigmf-meta` пишутся:
- `core:sample_rate` и центральная частота (`captures[0].core:frequency`) — те, что были настроены на момент сохранения;
- `core:hw` — тип и URI/серийник подключённого устройства (например, `PlutoSDR (usb:1.5.5)`);
- `core:recorder` (`"IQ Forge"`), `core:datetime` записи и необязательное `core:description`, которое можно вписать перед сохранением;
- **аннотации**: кнопка **Mark now** в разделе "Annotations" ставит метку на текущей позиции в записываемом буфере (с необязательным текстовым label) — список меток очищается вместе с буфером при Save & clear и попадает в `core:annotations` файла.

При **Load** на TX-панели `.sigmf-data`/`.sigmf-meta` (можно выбрать любой из двух — второй находится автоматически рядом) распознаётся сам: **sample rate восстанавливается автоматически** (поле "File sample rate" заполняется из `core:sample_rate`, использовать которое дальше — как обычно, через "Resample on load"). Центральная частота, hw, description и список аннотаций показываются под статусом загрузки; сама частота устройства при этом **не** переключается автоматически (это было бы неожиданным действием с реальным железом) — рядом есть кнопка **Apply to device**, если нужно перестроиться на неё явно.

Ограничение текущей реализации: пишется/читается ровно один `captures`-сегмент (без разбиения записи на несколько частотных сегментов) и датасеты `cf32_le`/`ci16_le` (наиболее распространённые для SDR-записей); прочие `core:datatype` из SigMF-экосистемы (`cu8`, `rf32_le` и т.д.) не поддерживаются.

### Визуализация

Каждое окно визуализации (TX и RX) объединяет в себе спектр, водопад, I/Q, фазу и мгновенную частоту — каждая панель включается/выключается своим чекбоксом.

**Freeze** — рядом с этими чекбоксами: ставит все графики этого направления (TX или RX по отдельности) на паузу, чтобы спокойно разглядеть/измерить статичную картинку — маркеры, зум, Shift-выделение по-прежнему работают. Сам приём/передача (и запись RX на диск, если включена) при этом не останавливаются, замирает только то, что нарисовано.

#### Водопад

Справа от водопада — панель с настройками отображения и компактной сводкой:
- **Grid** — сетка поверх водопада (по умолчанию выключена: иначе почти не видна под цветом, а если включить — рисуется поверх данных, а не под ними).
- **Colormap** — палитра (Viridis, Plasma, Hot, Jet, Greys).
- **Min/Max (dBFS)** — диапазон уровней, отображаемый цветом.
- **Bins / Rows / History** — сколько столбцов реально нарисовано, сколько строк истории накоплено и на какой промежуток времени она растягивается.
- **Last peak / Last peak freq** — уровень и частота максимума в самой последней развёртке.

Число отображаемых столбцов ограничено (1024) независимо от выбранного размера FFT — экран всё равно не покажет больше, а честная отрисовка десятков тысяч цветных прямоугольников на кадр заметно тормозит интерфейс. При даунсемплинге берётся максимум внутри группы бинов (а не среднее), чтобы узкий пик не размывался.

#### Управление масштабом (общее для всех графиков)
- **Колесо мыши** — зум по оси X.
- **Shift + колесо мыши** — зум по оси Y.
- **Перетаскивание (drag)** — панорамирование.
- **Shift + перетаскивание** — выделить диапазон, чтобы измерить именно его (см. ниже); отпустить — диапазон остаётся, приближает как обычный box-zoom. **Правая кнопка** во время выделения — отменить его.
- **Двойной клик** — сброс к автоподбору масштаба ("Fit signal").
- Кнопки **H+/H-/V+/V-** — зум по отдельной оси без мыши.

#### Спектр — маркеры и измерения
- **Маркеры M1–M4**: ставятся по **Ctrl+клик** по графику на выбранный (подсвеченный) маркер. Кнопки `M1`…`M4` над графиком выбирают, какой из маркеров сейчас "активен" для установки/поиска.
- **Peak search** — переносит активный маркер на самый сильный пик спектра.
- **Next peak** — переносит активный маркер на следующий по силе пик (поиск пиков учитывает превышение не менее 6 дБ над соседним провалом, чтобы шум не считался отдельными пиками).
- **-> Center freq** — перестраивает центральную частоту устройства на частоту активного маркера (если устройство подключено — переключает и реальное железо).
- **Delta ref** — выбор второго маркера как опорного: у активного маркера появляется показание Δ-частоты и Δ-амплитуды относительно опорного.
- **Clear** — снять текущий маркер.
- **Band marker** — включаемая полоса измерения: два края можно как перетаскивать мышью прямо на графике, так и задавать числами (Lo/Hi, Гц), либо просто **Shift + выделить** нужный диапазон на графике — полоса подставится сама, а её мощность/пик появятся и в панели управления, и подписью прямо под выделением. Показывает суммарную мощность в полосе и пиковое значение внутри неё.
- **Trace / peak hold / persistence**:
  - **Trace: Live / Max hold / Min hold** — режим отображаемой трассы (обычный live-спектр, накопление максимумов или минимумов по каждому бину). Кнопка **Reset hold** сбрасывает накопление.
  - **Peak hold** — независимый оверлей "пиковых значений с момента включения" (отдельно от режима Trace, можно включить одновременно с Live). **Clear peak hold** сбрасывает его.
  - **Persistence** — "послесвечение": на графике полупрозрачно остаются последние ~24 развёртки, более старые — более бледные. **Clear persistence** очищает историю.

#### Таблица измерений

Справа от спектра — компактная таблица, которая всегда считается автоматически (маркер ставить не нужно) по текущей развёртке и по сырому IQ-буферу:

| Показатель | Как считается |
|---|---|
| Peak freq / Peak level | частота и уровень глобального максимума спектра |
| Noise floor | медиана трассы (устойчива к паре узкополосных пиков) |
| SNR | Peak level − Noise floor |
| Occupied BW | самая узкая полоса, содержащая 99% суммарной мощности (по 0.5% отсекается с каждого края) |
| -3 dB BW / -6 dB BW | ширина главного лепестка вокруг пика на уровне −3 дБ и −6 дБ от него |
| Channel power | суммарная мощность по всей отображаемой полосе (интеграл по всем бинам) |
| RMS / Peak (time) | среднеквадратичное и пиковое значение \|I+jQ\| по сырому буферу сэмплов |
| Crest factor | Peak (time) − RMS |
| DC offset | уровень модуля среднего комплексного значения сэмплов относительно полной шкалы |
| Clipping | число (и доля) сэмплов с \|I\| или \|Q\| ≥ 0.999 — признак насыщения АЦП/ЦАП |

Второй набор измерений (SINAD, THD, SFDR, ACPR, frequency error, I/Q gain imbalance, quadrature error, EVM) пока не реализован — в планах.

#### Временная область — маркеры и триггер

Те же маркеры M1–M4, что и на спектре (Ctrl+клик — поставить выбранный), только общие сразу для трёх графиков — I/Q, фазы и мгновенной частоты: маркер, поставленный на одном, сразу виден на всех трёх.

- Кнопки `M1`…`M4` выбирают активный маркер, `Clear` снимает его.
- **Delta ref** — как и на спектре: у активного маркера появляется показание относительно выбранного опорного маркера — **dt** (интервал времени, он же измерение периода сигнала), **1/dt** (частота) и **dAmplitude** (разница |I+jQ|).
- **Shift + выделение** диапазона сэмплов на любом из трёх графиков — тоже общее для всех троих. Под маркерами появляется строка с RMS/Peak/Crest factor/DC offset/Clipping, посчитанными только по выделенному участку (та же формула, что и в таблице измерений спектра, только по сырому куску буфера, а не по всей развёртке).
- **Триггер** (панель над I/Q-графиком): включение, фронт (rising/falling), источник (I/Q/модуль), авто- или ручной уровень, размер окна. Текущий уровень триггера отображается на графике I/Q горизонтальной линией.

### Настройки и пресеты

![Панель Settings: автосохранение и пресеты](assets/screenshots/settings_presets.png)

Панель **Settings** (снизу, рядом с логом):
- **Save settings on exit / restore on startup** — включено по умолчанию: текущая конфигурация (устройство и его URI, sample rate/центральная частота/полоса, TX/RX gain, размер FFT, весь TX-генератор и файловый источник, формат/путь записи RX) сохраняется при закрытии приложения и восстанавливается при следующем запуске. Выключается тем же чекбоксом — само это состояние тоже запоминается, так что отключение переживает перезапуск.
- **Main area tabs** — какие из TX, RX, Signal Viewer и SpectrumViewer показываются вкладками в основной области; снятие галочки просто прячет вкладку, не останавливая ничего, что работает под капотом. SpectrumViewer по умолчанию скрыт.
- **Presets** — сохранить текущую конфигурацию под произвольным именем (**Save preset**), затем в любой момент подгрузить (**Load**) или удалить (**Delete**) из списка. Работают независимо от переключателя автосохранения выше — доступны, даже если оно выключено.

Файлы настроек и пресетов хранятся в `%APPDATA%\iqforge` (Windows) или `~/.config/iqforge` (Linux).

## Сборка

```sh
cmake -B build
cmake --build build
```

Требуются пакеты: GLFW, OpenGL, libiio, fftw3f и libhackrf. `imgui`, `implot`, `libsamplerate` и `nlohmann/json` (для чтения/записи SigMF) подтягиваются сами через FetchContent.

```
sudo apt update
sudo apt install libglfw3-dev libglu1-mesa-dev freeglut3-dev mesa-common-dev libiio-dev libfftw3-dev libhackrf-dev
```

## Запуск тестов

```sh
cmake --build build --target test
```
